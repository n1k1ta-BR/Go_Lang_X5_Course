# Сервис заказов

Учебный HTTP API на Go. Поддерживает создание и получение заказов, пагинацию, фильтрацию по статусу и отмену заказа. Документация доступна через Swagger UI.

## Запуск

Требуется Go 1.22 или новее. Команды выполняются из папки с `go.mod`.

```bash
go mod download
go generate ./...
go run ./cmd/orders
```

Сервер запускается на `http://127.0.0.1:8080`. Для остановки нажать `Ctrl+C`.

Swagger UI доступен по адресу `http://127.0.0.1:8080/swagger/index.html`. После изменения аннотаций выполнить `go generate ./...`, перезапустить сервер и обновить страницу.

Заказы хранятся в памяти и удаляются после перезапуска сервера.

## Маршруты

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/v1/status` | Проверить состояние сервиса |
| POST | `/api/v1/orders` | Создать заказ |
| GET | `/api/v1/orders` | Получить страницу заказов |
| GET | `/api/v1/orders/{id}` | Получить заказ по номеру |
| PATCH | `/api/v1/orders/{id}/status` | Отменить заказ |

## Создание заказа

POST принимает JSON с полем `customer`.

```json
{"customer":"Алиса"}
```

Успешный ответ имеет статус `201 Created`, содержит заказ и заголовок `Location` с его адресом.

```json
{"id":1,"customer":"Алиса","status":"new"}
```

Имя очищается от пробелов по краям. Пустое или пробельное имя возвращает `400 VALIDATION_ERROR`. Повторные заказы одного клиента разрешены.

## Список заказов

```http
GET /api/v1/orders?limit=10&offset=0&status=new
```

| Параметр | Значение по умолчанию | Допустимые значения |
|---|---|---|
| `limit` | `20` | Целое число от `1` до `100` |
| `offset` | `0` | Целое число от `0` до максимального `int` |
| `status` | Все статусы | `new` или `cancelled` |

Заказы возвращаются по возрастанию `id`. Фильтр применяется ко всему списку до выбора страницы. Пустая выборка и страница за пределами списка возвращают `200` с телом `[]`.

В числовых параметрах допустимы только десятичные цифры. Пустые значения, неверный формат, выход за диапазон, повторные и неизвестные параметры возвращают `400 INVALID_QUERY`.

После создания трёх заказов запрос `?limit=1&offset=1` возвращает массив со вторым заказом.

## Отмена заказа

PATCH принимает JSON с новым статусом.

```http
PATCH /api/v1/orders/1/status
Content-Type: application/json

{"status":"cancelled"}
```

Разрешён переход `new` в `cancelled`. Успешный ответ возвращает `200` и обновлённый заказ. Повторная отмена возвращает `409 ORDER_ALREADY_CANCELLED`. Проверка и изменение статуса выполняются атомарно под мьютексом.

## Ошибки

Ошибки API возвращаются в формате JSON.

```json
{"error":"order not found","code":"ORDER_NOT_FOUND"}
```

| Статус | Причина |
|---|---|
| `400` | Неверный идентификатор, параметры, JSON или значения полей |
| `404` | Заказ или маршрут не найден |
| `405` | Метод запрещён, разрешённые методы перечислены в `Allow` |
| `409` | Заказ уже отменён |
| `413` | Тело запроса превышает 1024 байта |
| `415` | Неподдерживаемый `Content-Type` |
| `500` | Внутренняя ошибка сервера |

POST и PATCH требуют `Content-Type: application/json` и один JSON-объект с известными полями. Допускается параметр `charset=utf-8`. Неизвестные поля, `null` и дополнительные JSON-значения отвергаются.

## Проверка

```bash
go generate ./...
go test -race ./...
go vet ./...
go build ./...
```

Тесты проверяют создание и чтение заказов, страницы списка, ошибочные параметры, фильтрацию, большой `offset`, отмену и конфликт при параллельных запросах.

Примеры запросов находятся в `requests.http`
